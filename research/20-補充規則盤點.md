## 第三節：未涵蓋且官方有公開格式之供應商（自建規則對象清單）

### 3. Fireworks AI

- **官方來源**：[Fireworks Querying](https://docs.fireworks.ai/guides/querying-text-models)、[Fireworks API Docs](https://docs.fireworks.ai/api-reference/introduction)

### 4. DeepSeek
- **機密類型**：API Key
- **官方公開格式規格**：固定前綴 `sk-`，後接 32 個十六進位小寫字元（`[a-f0-9]{32}`），總長度 35 字元。
- **官方來源**：[DeepSeek Docs](https://api-docs.deepseek.com/)、[DeepSeek Pricing](https://api-docs.deepseek.com/quick_start/pricing)

### 5. xAI / Grok
- **機密類型**：API Key / Ephemeral Token
- **官方公開格式規格**：固定前綴 `xai-`，後接英數字元字串。
- **官方來源**：[xAI Overview](https://docs.x.ai/docs/overview)、[xAI API Reference](https://docs.x.ai/docs/api-reference)

### 6. OpenRouter
- **機密類型**：API Key
- **官方公開格式規格**：固定前綴 `sk-or-v1-`，後接 64 個十六進位小寫字元（`[a-f0-9]{64}`），總長度 73 字元。
- **官方來源**：[OpenRouter API Overview](https://openrouter.ai/docs/api-reference/overview)、[OpenRouter Quickstart](https://openrouter.ai/docs/quick-start)

### 7. Supabase（僅限機密項，需排除公開項）
- **機密類型**：
  - 新版 Secret Key（後端管理專用，取代舊版 service_role）
  - 新版 Personal Access Token (PAT / CLI Token)
  - 舊版 `service_role` JWT（具有全庫管理權限，繞過 RLS）
- **官方公開格式規格**：
  - 新版 Secret Key：前綴 `sb_secret_`
  - 新版 PAT：前綴 `sbp_`，後接 40 個英數字元
  - 舊版 JWT：`eyJ...` 且 payload 中包含 `"role":"service_role"`
- **防誤報排除項**：
  - **嚴禁將 `anon` key（`role:"anon"` 的 JWT）或新版 Publishable Key（`sb_publishable_`）標記為洩漏**，兩者皆為前端公開金鑰。
- **官方來源**：[Supabase API Keys](https://supabase.com/docs/guides/api/api-keys)、[Supabase JS Repo](https://github.com/supabase/supabase-js)

### 8. Vercel
- **機密類型**：Personal Access Token (PAT) 與 OAuth Access Token
- **官方公開格式規格**：
  - PAT：固定前綴 `vcp_`，後接 24 個以上英數字元
  - OAuth Token：固定前綴 `vca_`，後接英數字元
- **官方來源**：[Vercel REST API](https://vercel.com/docs/rest-api)、[Vercel CLI Repo](https://github.com/vercel/vercel)

### 9. Clerk（僅限機密項，需排除公開項）
- **機密類型**：Backend Secret Key（後端 BAPI 驗證專用）
- **官方公開格式規格**：
  - 開發環境 Secret Key：前綴 `sk_test_`，後接機密字串
  - 生產環境 Secret Key：前綴 `sk_live_`，後接機密字串
- **防誤報排除項**：
  - **嚴禁將前端 Publishable Key（`pk_test_` 與 `pk_live_`）標記為洩漏**，此為前端載入實例之公開金鑰。
- **官方來源**：[Clerk Env Vars](https://clerk.com/docs/deployments/clerk-environment-variables)、[Clerk Node.js SDK](https://clerk.com/docs/references/nodejs/overview)

### 10. Resend
- **機密類型**：API Key
- **官方公開格式規格**：固定前綴 `re_`，後接英數字元（例如 `re_[a-zA-Z0-9_]+`）。
- **官方來源**：[Resend Create API Key](https://resend.com/docs/create-an-api-key)、[Resend Node Repo](https://github.com/resend/resend-node)

## 官方未公開固定前綴格式之供應商（不納入自定義正規式標的）

以下供應商經查證官方文件與官方 SDK，官方未公開固定前綴或特定字元規範，通常以不透明 Bearer Token 形式傳遞，依協議不強行臆測或編造正規表達式：
- **Together AI**：未明定固定前綴，官方文件範例為不透明字串或 64 位元十六進位字串。
- **Mistral AI**：未明定固定前綴，官方文件範例為 32 位元不透明英數字串。
- **Railway**：未明定固定前綴，官方提供 Project Token 與 Account Token，以 Bearer Token 傳遞。
- **Neon**：未明定固定前綴，官方文件說明為 64 位元/字元字串，以 Bearer Token 傳遞。
- **Upstash**：未明定固定前綴，REST Token 為隨機 Base64/英數字串，包含 Standard 與 Read-Only 類型。
