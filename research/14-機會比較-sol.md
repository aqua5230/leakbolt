# LeakBolt 與 20 個外殼缺口候選：機會比較

日期：2026-08-29

## 判法與證據邊界

只用這把尺：**包裝後，有沒有一個引擎作者做不到、或不想做的東西？**

分數不是「技術好不好」或「星數多不多」。0 分是可被作者快速收回的薄包裝；10 分是有強烈、難複製的非引擎層，且已有第一人稱付費意願證據。護城河是主因，付費證據用來調整可信度。

`research/11-機會盤點-外殼缺口.md` 只證明專案星數、活躍度、授權及 GUI（圖形介面）／MCP（模型上下文協定）缺口；沒有使用者訪談、預購、已付款或「我願意付多少」的資料。因此下列 20 項的 (c) 全是「無證據」。星數不是付費意願。作者意願也未經訪談；以下凡談「意願」，均是依專案目前形態做的**推測**，不是事實。每項 (b) 的現況依據與該項 (a) 所引的 `research/11` 小節相同；提出的資料、長尾流程或支援層則是評估推測，不能倒過來當需求證據。

`research/12-民怨排行榜.md` 只有 GitHub API 連線失敗訊息，不能支持任何需求判斷。背景所述 29 個 repo／最高 49 個 👍 未出現在該檔，本文不把它當可引用數據。

3. **stable-ts — 5.0**：詞彙、講者、校正與交付紀錄能形成工作流狀態；第三方 0 星 GUI 也顯示「做一個視窗」不足。（依據：`research/11` §一第 4 項）
4. **Toshi — 5.0**：連接器、ACL、相關性回饋與維運支援比搜尋引擎本身更難被一次補齊。（依據：`research/11` §一第 8 項；後半為產品推測）
5. **RapidOCR — 4.5**：多後端引擎適合被替換；真正可守的是客戶文件模板、修正紀錄及人工覆核流程。（依據：`research/11` §一第 2 項；後半為產品推測）

選這五個，不是因為它們星數最高，而是都能合理長出至少一項：使用者累積資料、長尾例外、持續營運或商業支援。其餘候選多為一次性的 GUI／MCP 轉接，作者補同一入口就會失去差異。

但五個都有同一個致命缺口：**沒有第一人稱付費意願證據**。`research/11` 沒找使用者，只找 repo。這個前五名是「值得做下一輪需求研究」的排序，不是「值得立刻換題」的排序。

## 三、跟 LeakBolt 正面比較

### LeakBolt：7.0/10

- **作者自己做的難度與意願**：難度中至高；意願低。gitleaks 官方有 CLI、GitHub Action（自動化工作流程）與 pre-commit 設定，技術上能補 GUI／MCP；但官方已宣告功能凍結，作者轉做 betterleaks，而 betterleaks 仍是 CLI。這是目前最直接的「作者不想做產品層」證據，不只是猜測。（證據：`research/01-開源競品-gitleaks生態.md` §1）
- **作者做不到／不想做的東西**：**有，但不是 GUI 本身。**
  1. 多種 Git hook（Git 事件腳本）工具與 Git 客戶端的安裝、健康檢查、被覆寫提示及長尾支援；現有規劃已明列 husky、lefthook、pre-commit、GUI client 與 `--no-verify` 等例外。（證據：`DECISION.md`「安裝方式」；`PLAN.md` §三、§四）
  2. 每位使用者累積的誤報分類與最小化本機資料。作者可以複製功能，卻拿不到既有使用者的分類歷史；不過這只是轉換成本，不是網路效應，護城河偏弱。（證據：`PLAN.md` §三階段二、§四第 5 點）
  3. 各 key 供應商的 revoke（作廢）導航、花費上限指引、複掃驗證、簽章規則包、回滾及支援期限。價值來自持續維護長尾和商業承諾，gitleaks 核心作者未必想做。（證據：`PLAN.md` §三階段二、§四第 3 點、§五）
- **第一人稱證據**：明顯勝過 20 個候選。`research/03` 有多則本人 commit／push 密鑰、帳單與工具抱怨；`research/10` 另核到 4 則 AI 把 `.env`／憑證檔 commit 進版控。這證明痛點存在，而且後果可高；也證明誤報、太晚通知與錯誤安全感是流程問題。（證據：`research/03-X社群需求盤點.md` §1、§2、§3、§4；`research/10-X痛點盤點-廣義.md` §1）
- **但不是直接付費意願**：兩份研究都沒有「我願意為 LeakBolt／這個流程付 $39」的第一人稱承諾。`research/02` 的競品價格只證明別家公司有定價，不等於目標使用者願買。因此 7.0 不是市場已驗證，只是這批題目中證據最完整。

### 前 5 名有人贏過 LeakBolt 嗎？

**沒有。**

borgmatic 的非引擎層可能比 LeakBolt 厚，但沒有付費第一人稱、使用者流程或競品定價研究，且另有 GPL 整合與高支援責任。其餘四名只有「引擎強、介面缺」及推測出的工作流。LeakBolt 至少已有：明確第一人稱災情、現有工具抱怨、競品與價格、安裝衝突、產品邊界及作者功能凍結證據。（證據：`research/01`、`research/02`、`research/03`、`research/10`、`DECISION.md`、`PLAN.md`）

換題還會讓這些研究資產歸零。新題必須先補齊買方、付費意願、競品、分發、技術長尾及作者意願，才能回到 LeakBolt 現在的判斷位置。這不是情感上的沉沒成本；它是尚未完成、但可直接降低下一步試驗風險的資訊資產。

## 四、明確結論

**留下，不換題。**

理由不是 LeakBolt 已有堅固護城河；它目前只有中等護城河。理由是 20 個候選都沒有同等需求證據，且多數只有可被官方收回的介面缺口。此時換題，是拿「已查到真痛但尚未驗證付款」換成「連真痛與付款都沒查」。

前五名輸在：

- **borgmatic**：非引擎層最強，但付款證據為零、GPL 整合有約束，且還原承諾會立刻帶來高支援責任。（`research/11` §一第 9 項、§三）
- **trafilatura**：長尾可形成護城河，但誰因哪種擷取失敗願付錢，完全未查。（`research/11` §一第 6 項）
- **stable-ts**：工作流可累積資料，但現有證據只顯示三個 0 星 GUI，沒有買方。（`research/11` §一第 4 項）
- **Toshi**：要形成護城河就得做完整搜尋維運產品，範圍遠超 GUI；沒有需求證據。（`research/11` §一第 8 項）
- **RapidOCR**：文件流程可能可守，但目前只有引擎活躍與 GUI 查無，沒有付費場景。（`research/11` §一第 2 項）

### 什麼條件下會反轉

任一候選同時做到以下三件事，才改判換題：

1. 出現可核對的第一人稱付費承諾、預付或付費試點，且購買的是長尾流程、累積資料或支援承諾，不是單純 GUI／MCP。
2. 有直接證據顯示引擎作者明確拒絕該產品層，或其專案邊界使其不會承擔；不能只從「目前沒有」推成「永遠不做」。
3. 用同等強度的付款試驗測 LeakBolt，LeakBolt 沒人付，而候選有人付。

另一個反轉條件：gitleaks／betterleaks 官方推出與 LeakBolt 相同的安裝共存、誤報記憶、處置閉環及長期支援，讓非引擎層消失。現有來源只證明它們尚未這樣做。（`research/01`；`PLAN.md`）
