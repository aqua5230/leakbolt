## 一、擋 vs 放行：業界怎麼做

| 工具 | 找不到執行檔時 | 證據 |
|---|---|---|
| git-secrets | 擋 | hook 直接呼叫 `git secrets --pre_commit_hook`，失敗回非 0 |
| talisman（原生 hook） | 擋 | 直接執行 `${TALISMAN_BINARY}`，不存在回 127 |
| detect-secrets | 擋 | 走 pre-commit 框架，框架擋 |
| trufflehog | 擋 | hook 直接執行 `trufflehog git file://.`，不存在回 127 |
| husky v8 / v9 | 擋 | 明確捕捉 127 並 `exit $c`，還會印 `command not found in PATH=$PATH` |
| pre-commit 框架 | 擋 | `hook-tmpl` 找不到就 `exit 1` 並印訊息 |
| lefthook | **預設放行**，`assert_lefthook_installed: true` 才擋 | `internal/templates/hook.tmpl` 的 `exit 1` 包在該條件裡 |
| gitleaks 官方 `scripts/pre-commit.py` | **放行**（見下節，這是它的 bug） | 已驗證 |

**八個裡有六個擋。LeakBolt 改成擋，站在多數慣例這邊。**

lefthook 是唯一預設放行的，但它自己的文件解釋為什麼該開 `assert_lefthook_installed`：
「This makes sure git hook won't omit lefthook rules if lefthook ever was installed.」
——跟 LeakBolt 這次的修復理由一字不差。

## 二、gitleaks 官方自己的 hook 有我們剛修掉的同一個 bug（已驗證）

Claude 直接抓 https://raw.githubusercontent.com/gitleaks/gitleaks/master/scripts/pre-commit.py 確認原文：

```python
if gitleaksEnabled():
    exitCode = os.WEXITSTATUS(os.system('gitleaks protect -v --staged'))
    if exitCode == 1:
        print('''Warning: gitleaks has detected sensitive information in your changes.
...''')
        sys.exit(1)
```

只在 `exitCode == 1` 時 `sys.exit(1)`。gitleaks 不存在時 shell 回 127，
條件不成立，腳本跑到底、回 exit 0，**帶密鑰的 commit 安靜通過**。
跟 LeakBolt 修復前的行為完全一樣。

結論：這題不能拿 gitleaks 當範本，LeakBolt 修完之後比它嚴謹。

## 三、值得抄的兩件事

### 1. 給一個「只關掉 LeakBolt」的開關

`git commit --no-verify` 會關掉**所有** hook。使用者同時有 lint、測試、LeakBolt 時，
為了跳過 LeakBolt 一次而把 lint 跟測試一起關掉，這個代價之前沒考慮到。

每一家都有針對性的開關：

| 工具 | 開關 |
|---|---|
| husky | `HUSKY=0 git commit ...` |
| lefthook | `LEFTHOOK=0` 或 `LEFTHOOK_EXCLUDE=<tag>` |
| pre-commit | `SKIP=<hook id> git commit ...` |
| gitleaks | `git config hooks.gitleaks false` |

**建議採 gitleaks 那種 git config 式**：`git config hooks.leakbolt false`。
理由：LeakBolt 本來就在讀 git config（`gitConfig` 函式現成）；存在 repo 設定裡而不是
環境變數，`doctor` 查得到，可以在關掉時報異常——這樣「關掉後忘記」不會變成無聲的洞。

### 2. 訊息裡印出 PATH

husky 的做法：`echo "husky - command not found in PATH=$PATH"`。

LeakBolt 現在只說「現在 PATH 上找不到它」，沒印 PATH 內容。印出來對診斷有直接幫助，
尤其 GUI git 工具的 PATH 跟終端機不同這種情況。

## 四、查了但**不要**抄的兩件事

### 1. `--redact`（已驗證會壞掉）

gitleaks 官方 `.pre-commit-hooks.yaml` 的 entry 是
`gitleaks git --pre-commit --redact --staged --verbose`，帶 `--redact`。

Claude 實測 `gitleaks git --pre-commit --redact --staged --report-format json --report-path -`：

```
  "Match": "REDACTED",
  "Secret": "REDACTED",
```

`--redact` 會把 JSON 的 `Secret` 欄位換成 `REDACTED`。LeakBolt 的
`prepareStagedFindings` 是拿 `finding.Secret` 去算 HMAC 指紋的，加了 `--redact`
所有命中都會算出同一個指紋，`leakbolt allow` 直接壞掉。**不要加。**

LeakBolt 本來就不會把密鑰印出來（`printStagedSummary` 只印檔案、規則、指紋），
不需要靠 `--redact` 保護。

### 2. gitleaks 自己的 Fingerprint 欄位

實測輸出是 `s3.py:aws-access-token:1`，也就是「檔案路徑:規則:行號」。
LeakBolt 的 `state.go` 明訂「永遠不存原始命中、檔案路徑或 hooksPath 原文」，
用的是 salt 加 HMAC-SHA256。LeakBolt 的做法在隱私上比較嚴，維持現狀。

## 五、順帶查到的維護風險：gitleaks 指令換代了（已驗證）

本機 `gitleaks --help`（8.30.1）列出的 Available Commands：

```
  completion  Generate the autocompletion script for the specified shell
  dir         scan directories or files for secrets
  git         scan git repositories for secrets
  help        Help about any command
  stdin       detect secrets from stdin
  version     display gitleaks version
```

**`protect` 與 `detect` 都不在清單上了。** 兩個指令目前仍能執行
（`gitleaks protect --help` exit 0，實測輸出與新指令一致），但已從說明中隱藏，
代表在淘汰路上。

LeakBolt 現在用的是：

- `prototype/scan.go` `scanStaged`：`protect --staged`
- `prototype/scan.go` `scanHistory`：`detect`
- `prototype/cmd/corpusbench/main.go` `scanFile`：`detect --no-git --source`

gitleaks 官方現在的寫法是 `gitleaks git --pre-commit --staged`。

實測 `gitleaks git --pre-commit --staged` 與 `gitleaks protect --staged` 輸出一致。
建議在 PLAN.md 記一筆：鎖版 8.30.1 期間不影響，但升版前要先把這三處換成新指令。
